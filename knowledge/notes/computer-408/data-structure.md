# 数据结构

### 数据结构概述

数据的逻辑结构：	1）线性结构：直接存取-数组，顺序存取-链表，字典结构-hash；

2）非线性结构：层次结构-树，群关系-图&集合；

数据的存储结构：1）顺序存储；2）链接存储（指针，引用）；3）索引存储（附加索引表建立key与地址的映射）；4）散列存储（由key可直接计算地址）；

算法是一个有限的指令集合，为解决某一特定任务规定的运算序列；有输入，有输出，确定性，有穷性，可行性；

算法的性能标准：正确性，可使用性，可读性，效率，健壮性，简单性；后期测试，前期估计；空间复杂度，时间复杂度；渐进分析，最好，最坏，平均情况：O-描述上限，Ω-描述下限，Θ-上下限相等；

O(1)< O(log n)< O(n)<O(n*log n)<O(n2) <O(n3) <O(2n) <O(n!) <O(nn)；

O(·)只是算法随规模n变化的趋势，但n较小时则不一定符合该趋势，如n=3时，反而有n3>2n> n!；


### 线性表

一般而言，线性表的元素数据类型是相同的；广义表则允许元素有不同的数据类型；线性表有两种存储表示：顺序存储和链式存储；

顺序表：元素的逻辑顺序与物理存放顺序一致；可顺序访问也可随机访问，时间复杂度为O(1)；插入和删除任意元素需移动后续所有元素，效率较低，时间复杂度为O(n)；

单链表：长度可以方便地扩充；只能顺序访问，遍历效率低，时间复杂度为O(n)；插入和删除元素只需修改相关结点的指针，较高效，但定位该元素需要顺序查找，总的时间复杂度仍为O(n)；

带头结点的单链表；循环链表（首尾相接），应用 — 约瑟夫问题；双向链表；

静态链表：数组中每个元素有一个link域，无需改变元素位置，改变link域即可改变元素的逻辑顺序；与单链表性能相似，但link域不是物理地址，只是元素在数组中的序号；


### 栈和队列

栈Stack是只允许在末端插入和删除的线性表，LIFO；栈可以由顺序表，也可以由链表构成；栈的基本操作：pop，push；若由单链表构成栈，则pop时必须删除结点，否则会造成内存泄漏；用顺序表存储栈时，有的将top指向真实的栈顶，有的则将top指向真实栈顶的下一个位置；

栈的应用

括号匹配 — 遇到左括号入栈，遇到右括号则将左括号弹出栈，若最后栈为空说明左右括号匹配；每种括号一个栈，即可匹配有多种括号的表达式（允许交叉），若不允许交叉，只用一个栈即可；

后缀表达式的计算 — 又称逆波兰式，RPN，栈内元素是操作数，顺序扫描RPN表达式，若是操作数则入栈，若为（双目）操作符op，则连续两次退栈，得到X，Y，计算X op Y，并把结果入栈；表达式扫描完成后，栈顶就是结果；

中缀表达式转为后缀表达式 — 栈内元素是操作符后缀表达式，需考虑各操作符的栈内优先级ISP和栈外优先级ICP，主要是左右括号的优先级变化；顺序扫描中缀表达式，若为操作数则直接输出，若为操作符op，判断其栈外优先级与栈顶操作符top的栈内优先级，若op.ICP>top.ISP，则将op入栈，继续扫描；若op.ICP<top.ISP，则退栈并输出top，op继续与新的top比较，直到遇到较小ISP或栈空，将op入栈，继续扫描；若op.ICP==top.ISP，退栈但不输出，继续扫描；

用栈实现函数调用，递归，显式递归（回溯法）；

队列是只允许在末端插入，在首端删除的线性表，FIFO；

循环队列（队尾指向的是下一个末端的空位，即队列至少有一个空闲位）：

出队 front=(front+1)%size; 		入队 rear=(rear+1)%size;

空	front==rear；				满   (rear+1)%size==front；

元素个数 (rear – front + size)%size；

队列应用

计算二项式的系数（杨辉三角） — 输出当前行时，就可以计算出下一行并入队，各行间需插入一个0；

电路布线，迷宫 — 用队列跟踪那些已经被标记，但其相邻点尚未标记的点；全部点都标记后回溯；

优先级队列：不是FIFO队列，每次从队首取得的是优先级最大的元素；可以用一般队列实现，在插入或删除后需调整队列，将优先级最大的元素移动到队首；也可用堆（heap）实现；


### 数组、串和广义表

多维数组，行优先存储；特殊矩阵（对称阵，上、下三角阵等）的存储；

稀疏矩阵(sparse matrix)：三元组存储（行，列，值）；正交链存储；

字符串；子串的模式匹配：朴素算法，有回溯，O(n*m)，适合较短的字符串；KMP算法，无回溯，需计算next函数以反映子串自身的模式，O(n+m)；Boyer-Moore算法：从子串尾部开始比较；

广义表，递归定义的，允许表中有表，类似LISP中的list；有序，有长度，深度，递归的；


### 树

注：满二叉树；完全二叉树，完全二叉树的叶结点可能在k和k-1层；二叉树的性质

二叉树的第i层最多有2i-1个结点，注意：以根结点所在的层为第1层；

深度为k的二叉树最少有k个结点，最多有2k-1个结点；

对任一棵非空二叉树，如果叶结点数为n0，度为2的非叶结点数为n2，则n0=n2+1；
边数，又有，由此即可得上面的性质；

有n个结点的完全二叉树的深度为ceil(log2(n+1))；

若将完全二叉树从上到下，从左到右顺序存储，结点编号1~n，则有

若结点编号i==1，则为二叉树的根结点；若i>1，则其父结点为floor(i/2)；

若2*i  <=n，则结点i的左孩子为结点2*i  ；否则没有左孩子，当然也就没有右孩子；

若2*i+1<=n，则结点i的右孩子为结点2*i+1；否则没有右孩子；

若结点i为奇数且≠1，则它处于右兄弟位置；

若结点i为偶数，则它处于左兄弟位置；

若完全二叉树结点编号0~n-1，则

若结点编号i==0，则为二叉树的根结点；若i>0，则其父结点为floor((i-1)/2))；

若2*i+1<=n-1，则结点i的左孩子为结点2*i+1；否则没有左孩子，当然也就没有右孩子；

若2*i+2<=n-1，则结点i的右孩子为结点2*i+2；否则没有右孩子；

若结点i为偶数且≠0，则它处于右兄弟位置；

若结点i为奇数，则它处于左兄弟位置；

若u为unsigned int，则floor(u/2)=u/2，ceil(u/2)=(u+1)/2=floor((u+1)/2)；ceil(u/2)≠u/2+1；

ceil(log2(u+1))是u最高非0位（左边第一个1）的位数（从右向左数，依次为1~32位），如8用二进制表示为1000，最高非0位在第4位，得ceil(log2(9))=4，可通过连续左移实现；

搞不清上面关系时画一个简单的二叉树带入比较一下即可很快得出结论；

n个结点能构成二叉树的个数为，称为catalan函数，这也是n个编号的元素以某种顺序进栈，任意顺序出栈（即进出栈可以交替进行），得到的元素排列的个数；

二叉树的存储

完全二叉树可以从上到下，从左到右顺序存储在一维数组，但注意数组应从1开始编号，以方便相关计算；

一般二叉树可预留空位后按完全二叉树存储；也可用二叉链表存储；为了方便寻找父结点，增加一个父指针域，成为三叉链表；二叉和三叉链表都可用静态链表结构；亦可用仅有父指针的静态链表来存储；

二叉树的遍历

递归算法：前序VLR（树的复制，相等，广义表格式打印），中序LVR，后序LRV（结点计数，高度）；

void Traverse(BinTree & tree, void (* visit)(BinTree & node)){

if(tree!=NULL){

Traverse(tree.left,  visit);

visit(tree);                  //VLR, LVR,LRV差别只在visit的顺序；

Traverse(tree.right, visit);

}

}

非递归算法，需要一个栈实现显式递归，后序(LRV)还需要增加辅助标识，以区分L,R；

由给定的前序（后序）和中序序列能唯一确定一棵二叉树；

层序遍历（广度优先），需要一个队列，在访问某一层时，将下一层的结点入队；

void LevelTraverse (BinTree& tree, void (* visit)(BinTree & node)){

Quene* q= new Quene();

q->EnQuene(tree);

while(!q->IsEmpty()){

tree=q->DeQuene();    visit(tree);

if(tree.left !=NULL) q->EnQuene(tree.left);

if(tree.right!=NULL) q->EnQuene(tree.right);

}

delete q;

}

线索二叉树：n个结点的二叉链表中有n+1个空指针，可以利用其指向前驱或后继结点，称为线索，这时每个指针域需附加一个标志域，以区分指针指向的是子树还是线索；二叉树的不同遍历方法对应了不同的线性序列，线索即指明了这种线性序列的前驱/后继关系；

线索二叉树的遍历；建立线索的方法；插入和删除结点的方法；中序线索实现前序和后序遍历；

树的度是所有结点的度的最大值；一般树的存储：1）广义表（即链表）；2）父指针，父结点和子结点是1:N的关系，每个子结点只需要一个父指针；3）孩子链表，每个结点有一个链表，保存所有孩子结点，还可以与父指针法结合起来；4）孩子-兄弟链表，又称长子-兄弟链表，是一种二叉树表示法，由长子(firstChild)域指出第1个子结点，由兄弟(nextSibling)域将同一个父结点的其它结点串成链表；

树与二叉树的转换：利用长子-兄弟链表表示法，连线-剪枝，即将各兄弟结点连接起来，然后剪断除长子结点外其它兄弟结点与父结点的边，这样形成的二叉树的根结点没有右子树，原来的长子结点都在左子树，而它的兄弟结点则成为其右子树上的结点；

森林与二叉树的转换：先将各树转换为二叉树，然后把每棵树的根结点连到上一棵树的右孩子上；

树与森林的遍历：深度优先（先根↔先序，后根↔中序，可借助长子-兄弟链表法，用二叉树的遍历来实现）；广度优先（层次）；

最小堆MinHeap：任一结点的key均≤它的左、右孩子的key，堆顶（根结点）的key是整个堆（树）最小的；即堆是递归定义的，每个堆的子树也是一个堆；注：堆的左、右孩子之间没有确定的大小关系，这与搜索树不同；

堆是一棵完全二叉树，一般采用数组顺序存储，可根据下标直接计算出其父子结点；

下滑(siftDown)：从某个父结点开始向下比较，如果父结点＞左/右孩子中最小的那个，则交换该父结点和最小的子结点，这样逐层向下调整，直到最下一层（叶结点）；

上滑(siftUp)：从某个结点开始向上比较，如果该结点＜父结点，则交换该结点和其父结点，这样逐层向上调整，直到堆顶结点；

建立堆：一种方法是从空堆开始逐个插入结点；另一种是对一般的完全二叉树就地加以调整，即从最后面的一个非叶结点（从0开始编号，为floor((i-1)/2))，即最小的一个子堆）开始，直到根结点，对所有非叶结点从后向前逐个执行siftDown调整，自底向上逐步扩大，将各子树局部均调整为堆；时间复杂度均为O(n*log2 n)；；

插入结点：新结点总是插入到已形成的堆的末尾，然后siftUp调整，O(log2 n)；

删除结点：总是删除堆顶结点，然后将最后一个结点移到堆顶，最后再执行一次siftDown调整；O(log2 n)；

由树的定义可知，从根到达树的每个结点有且只有1条路径；扩充二叉树是给所有叶结点赋权的二叉树，非叶结点则没有权值；整棵树的带权路径长度为各叶结点权值与路径长度乘积的和，即；

Huffman树是带权路径长度最小的树；Huffman树不是唯一的；构造算法：

在全部结点中选择权值最小的2个构成一棵树的左、右子结点，其根为这2个子结点权之和；

将上述子树的根作为一个结点，与其它结点一起比较，在这些剩余结点中选择权值最小的2个构成一棵树的左、右子结点，其根为这2个子结点权之和；可以用最小堆帮助找到最小的结点；

重复上述步骤直到没有结点剩余；

Huffman树没有度为1的结点，只有度为0和2的结点；Huffman编码，一定是前缀编码；最优判定树；


### 集合与字典

集合中没有重复的元素；

位向量实现集合：对有限集合，可以建立到自然数0,1,2…n-1的映射，它的每个子集都可以用一个n位的向量来表示，利用位运算很容易实现集合的相等，并，交，差，补等运算；

有序链表实现集合：可以表示无穷集合的子集；有序排列便于实现各种运算；

并查集(union-find set 或disjoint set)，支持Union，Find操作；实现并查集的典型方法是采用树（父指针的静态链表方式）来表示元算及其所属子集的关系；合并子集时，将某个子集的根作为另一子集的子结点即可，为提高Find的效率，应将小的子集合并到大的子集下面；为进一步提高Find效率，可进行压缩路径操作，即将各子结点的父结点都置为根结点；

等价关系：自反性，对称性，传递性；一个集合S中的所有元素可通过等价关系划分为若干互不相交的子集，这些子集称为等价类；利用并查集划分等价类，最初每个元素自成一个等价类，之后每处理一个等价对i≡j时，先要确定i，j所在集合（Find），如果是不同的集合，则将这2个集合合并（Union）；

字典是<key-value>的集合，基本操作是Find，Insert，Remove；

跳表是有序链表为了方便二分搜索，在首、尾、中间的结点各增加一个指针域的结构；跳表可以有多级；

散列Hash是将元素的key通过某种较快速的算法直接映射到存储位置，从而直接访问的结构；Hash必须考虑冲突问题，冲突太多会显著降低效率；

散列算法要求定义域必须包括全部可能的key，计算出的地址应均匀分布，算法简单，高效；常用的算法有：

取模：hash(key)=key % p，p是一个不大于容量m的质数；常用；

其它：数字分析法，分析各key中数值的分布规律；平方取中法；折叠法：又有移位法，分界法等；

处理冲突的闭散列方法，发生冲突后占用另外的码位，不能直接删除表中元素，只能标记为已删除（或删除元素后移动后续受影响的全部元素），不适合经常变动的情况；

线性探查法，如果有冲突，则放到下一个空位处，(H+i)%size，即H+1,H+2,… ；

二次探查法，(H+i2)%size，(H-i2)%size，即H+1,H-1,H+4,H-4,… ；

双散列法，采用两种不同的散列方法；

处理冲突的开散列方法，用链表（桶）保存同义词，链表内一般采用顺序搜索；

填充因子=已有记录数/预设最大记录数，表明了发生冲突的可能性，不应过大；


### 搜索结构

为保持较高的效率，搜索结构在插入和删除等操作后会调整，结构可能发生变化，称为动态搜索结构，反之则称为静态搜索结构；衡量搜索算法效率一般用平均搜索长度ASL，或磁盘IO次数（外部搜索）；

静态搜索结构：1）顺序搜索；2）有序表的折半搜索：mid=low+(high-low)/2，亦即(high+low)/2，但直接相加可能会溢出；判定树，失败结点=叶结点；3）索引顺序表；

二叉搜索树，是构造出的类似折半搜索的判定树那样的树形结构；其特点是左子树（若不为NULL）上所有结点的key＜根结点；右子树（若不为NULL）上所有结点的key＞根结点；这是递归定义的，每棵子树也都是二叉搜索树；若中序遍历二叉搜索树，则得到的序列是从小到大有序排列的；ASL≤Height；

二叉搜索树的插入：首先搜索二叉树，检查新插入的元素是否已经在树中，如果已存在，则无需操作；如果不存在，则将其插入搜索停止的结点的左/右子树处；

二叉搜索树的删除：若为叶结点，直接删除；若仅有左/右子树，则用左/右子树顶替被删除的结点；若既有左子树，又有右子树，则在右子树中找到key最小的结点，填补到被删除结点位置上，这是一个递归的过程；

若不同的key有不同的搜索概率，则ASL最小的称为最优二叉搜索树；

AVL树又称高度平衡的二叉搜索树，right.Height - left.Height的绝对值不超过1，即只能为-1,0,1，这样可以减少ASL，提高搜索效率；在插入，删除后要调整结构，以保持平衡；

### 图

基本概念

有向图；无向图；不考虑顶点有自环的情况，也不考虑任意2个顶点间有多重边的情况；

完全图：任意2个顶点间都有边相连，无向图的边数为n(n-1)/2；有向图为n(n-1)；

简单路径，路径上各顶点没有重复；回路/环，路径上首个顶点和最后一个顶点重合；

连通图与连通分量，任意2个顶点之间都有路径；非连通图的极大连通子图叫做连通分量；

强连通图与强连通分量：对有向图，每2个顶点之间都存在正反2条路径；非强连通图的极大强连通子图叫做强连通分量；

生成树(Spanning tree )：对无向连通图，是其一个极小连通子图，由n-1条边构成；

图的存储结构，不同的存储结构适合不同的处理算法；

邻接矩阵：大小为n*n，若边数较少，则矩阵很稀疏，存储利用率低；无向图是对称阵，有向图则不对称；

邻接表：有一个顶点表，按编号顺序保存全部顶点，每个顶点带一个链表，是与此顶点相连的其它顶点在顶点表中的编号，即边的信息；对无向图，每个边保存2次，有向图则只有一次；有向图的每个顶点可带一个出边链表，和一个入边链表；边链表的每个结点还可以增加权值域；

邻接多重表：特别适合以边为处理对象，每条边处理一次的算法；这种方法也有一个顶点表，顺序保存全部顶点；但表示边的链表与邻接表不同，每个结点表示一条边，有5个域，分别为Mark，Vertex1，Vertex2，Path1，Path2；Vertex1，Vertex2是该边的2个顶点；Path1，Path2分别指向Vertex1，Vertex2的下一个边结点，这样就分别组成了各自的边链表；没有重复保存边

无向图的顶点表中每个顶点是其边链表的头指针，遍历边时要将当前结点编号与Vertex1，Vertex2比较，以判断是选择Path1还是Path2；

有向图的顶点表中每个顶点分别有一个出边链表的头指针和一个入边链表的头指针；

图的遍历，为了处理回路，需要标识已经访问过的顶点，

深度优先DFS，递归算法：访问本结点，然后对未访问过的各邻结点DFS；

广度优先BFS，非递归，按层访问：出队，访问本结点，将所有邻结点入队，如此循环直到队列为空；

最小（代价）生成树MST (Minimum-cost spanning tree )，一个连通图的生成树必有n-1条边，且这些边不能构成环路；带权图的MST不是唯一的；下面的算法都属于贪心( Grady )算法

Kruskal算法：初始时只有顶点，没有边，然后逐步从边集E中取出权值最小的边，如果该边与已有的边不构成回路（准确的说，是该边的2个端点不在同一连通分量上），则加入；如此重复，直到加入的边数为n-1（或边集E已空）；O(e*log e)？，适合稀疏图；

用最小堆来查找权值最小的边；利用并查集的查找运算来判断任一边的2个顶点是否来自同一连通分量，用并查集的合并运算将新加入的边的顶点各自所在的2个连通分量合为1个连通分量；

Prim算法：始终将顶点集合分成不重叠的2部分，已在MST中的顶点集合Vmst和其它剩余顶点集合V-Vmst，称为该图的一个割（cut），2个集合之间至少有一条边相连，称为桥，从多个桥中选出权值最小的，其2个顶点有一个在Vmst，另一个在V-Vmst，将后者移入Vmst，并从边集E中删除该桥；如此不断扩大Vmst，直到其中的顶点数为n，这时里面有n-1条边；O(n2)，适合稠密图；

也利用最小堆来查找权值最小的边，Vmst每增加一个顶点，需将其另一顶点不在Vmst中的边插入堆中；

最短路径

非负权值的单源最短路径，Dijkstra算法：

为了寻找从源点V0到终点Vt的最短路径，依次将各中间点Vp加入到最短路径点的集合S中，计算出源点经该中间点到其余所有点V-S的最短路径，对集合V-S中的点Vk，如果V0经Vp到Vk的路径比上一轮得到的最短路径还要短，则更新源点V0到Vk的最短路径，记录到与Vk对应的辅助单元，并记录下该中间点Vp的编号，以作为回溯的线索；distance[k]=min(distance[k], distance[p]+weight(p,k))

若集合V-S中的点Vq是这一轮中与V0的距离最小的，则将其移入最短路径点的集合S，实际上每个点只需一个标志域，对已到达的点做标记，就能区分该点是在集合S还是在集合V-S了；

按上述步骤逐步扩展S，直到终点Vt，源点V0到所有顶点的最短路径都得到了，自然也就找到了源点V0到终点Vt的最短路径；

从终点开始，根据记录的上一个中间点，逐步回溯到源点，逆序输出，就得到完整的路径；

图中任意2个顶点之间的最短路径，各边权值均为正数，Floyd算法：如果用Dijkstra算法，可依次以各顶点为源点，每次可计算出该点到其余各点的最短路径，n次就可得到任意2个点之间的最短路径；而Floyd算法形式上更直接一些；Floyd算法原理与Bellman-Ford算法基本相似，也是利用了递推公式，图采用邻接矩阵存储，用一个n*n的矩阵A来保存每次迭代的最短路径，另外用一个n*n的矩阵Path来记录路径，A初始化为A-1[i][j]=weight(i,j)

Ak[i][j]=min(Ak-1[i][j], min(Ak-1[i][r] + Ak-1[r][j]|r=0,1,…n-1))

Pathk[i][j]=使上式取得最小值的r

注意k从0~n-1；

为了确定i到j的最短路径，若Pathn-1[i][j]=s，Pathn-1[i][s]=t，Pathn-1[i][t]=u，…，Pathn-1[i][v]=i，则路径为i→v→…→u→t→s→j；

用顶点表示活动的网络AOV (Action on Vertex)：AOV是一个有向无环图DAG (Directed Acyclic Graph)，用来表示项目的流程；AOV中各顶点存在着前驱/后继关系，拓扑排序可将各顶点排列成一个线性的有序序列，使得AOV中存在的所有前驱/后继关系都得到满足，但处理过程中会导致人为增加一些前驱/后继关系；若通过拓扑排序能将AOV的全部顶点都排入一个序列中，说明该AOV网络中没有有向环；否则存在有向环，说明该流程不可行；

拓扑排序的算法为

计算AOV各顶点的入度（直接前驱的个数）；

选择入度为0（没有直接前驱）的一个顶点输出；

从AOV中删除该顶点和它发出的所有有向边（该点入度为0，故没有指向该顶点的有向边），即将该顶点指向的所有顶点的入度减1；这时可能产生多个入度为0的顶点，为避免后续反复搜索顶点表中入度为0的顶点，可将它们压入一个栈保存起来（使用一个可变长的数组或队列保存这些顶点都是可行的）；

从栈中弹出一个入度为0的顶点，重复上步，删除该顶点和它发出的所有边，保存新产生的入度为0的顶点，直到没有入度为0的点为止（栈为空）；如果这时AOV中还有顶点，说明该AOV存在有向环；

一个AOV的拓扑有序序列不是唯一的；

拓扑逆序是在上述算法中每次删除出度为0的顶点及指向该顶点的有向边；

用边表示活动的网络AOE (Action on Edge)：同样用来表示项目的流程，但活动用有向边来表示，边的权值代表该活动持续的时间，顶点则表示活动的开始或结束事件；AOE也不存在有向环，且只有一个入度为0的顶点，称为源点，记为V0，即项目的开始事件，也只有一个出度为0的顶点，称为汇点，记为Vn-1，是项目的结束事件；

从源点到汇点的所有路径中，最大长度的路径称为关键路径Critical Path，这是完成整个项目所需的最短时间；

记VEarly[i]为顶点Vi的最早可能开始时间，须前面活动都完成了，Vi才能开始；即源点V0到Vi的关键路径长度；

记Vlast[i] 为顶点Vi的最迟允许开始时间，须保证项目按时完工，是以Vi为源点，到汇点Vn-1的关键路径长度；

活动Ai是以顶点Vi为起点，到顶点Vj的有向边，duration(i,j)是Ai持续的时间，即所需的工期；

记Early[i]为活动Ai的最早可能开始时间，可知Early[i]=VEarly[i]；

记Last[i] 为活动Ai的最迟允许开始时间，可知Last	 [i]=VLast[j] - duration(i,j)；

Last[i]-Early[i]称为活动Ai的松弛时间，是最早开始时间与最迟允许开始时间的裕量；

在关键路径上的活动，其松弛时间必为0，即Last[i]=Early[i]；计算出所有活动的松弛时间，为0的即为关键路径上的活动；

VEarly[i]的递推公式为：

VEarly[0]	= 0；

VEarly[i]	= max(VEarly[k] + duration(k,i)|k)，Vk是Vi的所有直接前驱，即要求各顶点是拓扑排序的；

从源点向终点依次递推，最终到达终点，VEarly[n-1]，就是项目的总工期；

VLast[i]的递推公式为：

VLast[n-1]	= VEarly[n-1]，这是上一步得到的项目的总工期；

VLast[i]		= min(VLast[j] - duration (j,i)|j)，Vj是Vi的所有直接后继，即要求各顶点是拓扑逆序的；

从终点向源点反向递推；

再由VEarly[i]，VLast[i]和duration (i,j)，计算出各活动的Early[i]和Last[i]，并计算出松弛时间，就找出了关键路径上的活动；


### 排序

排序算法的稳定性；内部排序与外部排序；性能评估：数据比较次数和数据移动次数；

插入排序，对基本有序的序列比较高效

直接插入排序：当插入第i个元素时，前面的0~i-1个元素已经有序，只要将i与这些元素从后向前依次比较，即可找到正确的位置，并将后面的元素依次移动；

折半插入排序：又称二分法插入排序，在寻找i的插入位置时采用折半搜索；

希尔shell排序：又称缩小增量排序；先取一个gap，将全部元素分为gap个序列，所有距离为gap的元素放在一个子序列里，在每个子序列进行直接插入排序；然后缩小gap重复上述子序列划分和排序，直到gap=1；各gap必须是互质的，可取gap=floor(gap/3)+1；排序开始阶段gap较大，每个子序列元素较少，排序速度较快，到后期，大多数元素已基本有序，也使排序速度较快；

交换排序

冒泡排序：从n-1号元素开始，相邻的两个元素相比较，如果逆序则交换，使最小的元素到达0号位置，然后对1~n-1号元素组成的子序列继续上述操作；

改进方法：若一轮比较后没有元素交换，说明序列已经有序，则结束排序，需一bool量记录是否发生了交换；

快速排序：是一种分治算法；任取某个元素作为基准，将整个元素序列分为左右2个子序列，左侧子序列中所有元素都＜该基准，右侧子序列中所有元素都＞该基准，基准元素的位置即最终排序后的位置；然后分别对左，右2个子序列递归执行上述操作，直到子序列长度为1；

快速排序的最坏情况是序列本来就有序（包括正序或逆序）的情况，当元素个数较少时，往往比简单排序方法还要慢；因此有改进算法先执行快速排序几个迭代，得到基本有序的序列，再执行直接插入排序，或当划分后的序列较小时改用插入排序；

基准元素的选择也会影响快速排序的效率，一种办法是随机选择，另一种是取首、尾、中部三个值的中间值；

三路划分的快速排序是处理有较多相等元素情况的算法；

选择排序：适合选取top i这样的需求；

直接选择排序：将一组元素中的最小值放置在首位，然后对剩余的元素重复上步，直到剩余1个元素为止；

锦标赛排序：利用胜者树/败者树，是稳定的；时间复杂度为O(n*log2 n)，需要n-1个辅助空间；

堆排序：将一维数组视为顺序存储的完全二叉树，逐步siftDown，将其调整为最大堆，然后将堆顶（0号，最大值）与最后一个（n-1号）元素交换，将0~n-2号元素视为堆，siftDown调整后，再将新的堆顶与n-2号交换，如此重复，直到堆内只有1个元素为止；

归并排序：将待排序的n个元素分成前、后2个长度相等的子序列，为每个子序列排序，然后再将它们合并为一个序列，这称为两路归并排序，可递归实现；归并两个长度分别为m，n的有序序列最坏的情况需比较m+n-1次；

上述的排序算法都是基于数组实现的；用链表则无需移动元素，亦可用静态链表，排序完成后再顺序输出；

分配排序：非比较算法；多个key的排序；分配，元素从桶上面依次进入；收集，元素从桶下面依次移出；

桶式排序

基数排序：高位优先MSD；低位优先LSD，从最低位到最高位，每位作为key做一轮分配和收集（排序），要求每轮排序必须使用稳定的算法；

交换类排序和选择类排序在每轮排序后，已处理过的元素所在的位置即是最终有序状态下的位置；而插入排序和归并排序没有这个特点；

注1：快速排序在序列已经有序（正序或逆序）时为最坏情况，而其它方法一般是正序为最好情况，逆序为最坏情况；

注2：基数排序中d指数字的位数，r是每位数字的范围；这虽然是线性的复杂度，但辅助操作，如截取各位的key消耗的时间是比较大的，所以大多数情况不一定比快速排序效率高；


### 文件、外部排序与搜索

稠密索引，稀疏索引；

倒排文件；次索引的二进制位矩阵法；

外排序需要多次从外存与内存间交换数据，决定效率的关键在于减少外存的IO次数；多使用归并排序，增大归并路数k，可减少IO次数，但路数过多，每次交换的数据量小，又会增加IO次数，k的选取与内存的缓冲区大小和磁盘性能都有关，需综合考虑；k路归并对应正则k叉树，即只有度为0（叶结点）和k的结点的树；

归并排序分两个阶段

将文件中的数据分段输入到内存，然后用某种内部排序方法对其排序，得到初始归并段，然后将其写回外存；

对多个初始归并段多遍归并，最终形成单一的归并段，就完成了外排序；

初始归并段的生成，采用置换-选择排序方法：当工作区满后（初始从输入缓冲区复制数据），将工作区调整为败者树，选择最小的元素输出到归并段（输出缓冲区），然后从输入缓冲区获取新的元素，如果新元素比当前归并段的最后一个元素（亦即最大者，可看做动态的门槛值）要小，则不能作为当前归并段的一部分，只能等待下一个归并段，将其放至工作区首（或尾，只要是固定位置顺序放置即可），当前工作区（名义）容量减少一个单元，否则就将其放入插入工作区已形成的败者树中，选出比当前归并段门槛大的最小值，插入归并段尾；重复上述操作，直到所有新输入的元素都不能加入当前归并段，即工作区（名义）容量为0，完成当前归并段，恢复工作区（名义）容量，开始生成下一归并段，直到全部数据都处理完；

常规方法每次的归并段大小等于工作区容量，而采用置换-选择排序方法生成的归并段都大于或等于工作区容量，最好的情况是输入的元素是有序的，则只生成一个归并段，最坏的情况是输入的元素是逆序的，生成的归并段大小等于工作区容量，平均情况的归并段长度不同；

置换-选择方法生成的归并段长度不同，在第2阶段归并时，让元素少的段先归并，元素多的段后归并，于是有最佳归并树的概念，即带权路径长度WPL最小的正则k叉树；k路最佳归并树可参考二叉树的Huffman算法，初始状态，叶结点是各归并段的长度，每次合并k个最小结点，并将其和作为根结点的值，作为一个新结点，继续参与合并；每个叶结点到根结点的路径长度是该结点参与归并的次数，每次归并有2次IO（I算一次，O算一次），若每个归并段的n个元素分别读写，则一个归并段本身需要n次IO，完成全部归并需要的IO次数=2*WPL；

败者树也是一棵完全二叉树，采用一维数组存储，必须从1号下标开始存储（0号单元用来保存整棵树的胜者）；归并用的败者树的内部结点和叶结点的类型不同，叶结点是数据元素，在k路归并算法中对应k个归并段的队首，仍存储在各归并段，败者树实际只有内部结点，其值为对应归并段的编号；

败者树没有度为1的结点，只有度为2的内部结点和度为0的叶结点；由二叉树的性质，n2=n0-1；

k路归并的败者树有k个叶结点，编号从k~(2k-1)（对应0~k-1号归并段，归并段从0开始编号），有k-1个内部结点，编号从1~(k-1)（加上0号单元，败者树的大小恰好为k）；

第i号叶结点（对应i-k号归并段）的父结点为floor(i/2)号；

父结点总是保存2个子结点中的败者对应的归并段编号，若从小到大归并，则小的元素是胜者，大的是败者；

建立树时，从最后一个叶结点开始，2个子结点组成一个小组进行比较，将败者的归并段编号保存到它们的父结点，胜者的归并段编号保存到父结点对应的辅助单元；这样对应每个父结点都需要一个辅助单元保存胜者的编号，即一个大小为k-1的辅助数组；

由各结点的编号i，可知此结点在第ceil(log2(i+1))层（根结点为第1层），决定了此结点参与比赛的轮次；第1轮比赛都在叶结点之间进行，但有部分叶结点直接晋级下一轮比赛，第2轮有可能是叶结点之间的比赛，也可能是叶结点和内部结点的比赛，或内部结点之间的比赛；

下一轮仍从后向前，即本层最右边结点开始进行比较，但有内部结点参与的比赛规则有变化；若右兄弟若为叶结点，左兄弟结点为内部结点，则叶结点与胜者，即左兄弟对应的辅助单元比较，将败者的归并段编号保存到父结点，胜者编号保存到对应的辅助单元；若左、右兄弟均为内部结点，则分别将其对应的胜者，即分别对应的辅助单元相比较，败者编号存入父结点，胜者编号存入对应的辅助单元；

重复上述步骤，直到第3号结点与第2号结点比较，败者编号保存到其父结点（1号），即根结点，将胜者编号保存到败者树存储数组的0号结点（辅助单元可用可不用），这是k个叶结点中最小元素的归并段编号，至此败者树建立完成，比较的次数为内部结点个数，即k-1；

k路归并时，将败者树的胜者，即0号结点对应的归并段队首放到生成的归并段尾，败者树空缺的位置由原归并段下一个元素替补，这时需要调整败者树，方法是将新元素与父结点保存的败者编号对应元素进行比较（这里需要一个辅助单元保存刚才取走的元素），将败者的编号保存到父结点，胜者继续与上一级父结点保存的败者比较，直到根结点；

上面建立败者树的方法比较复杂，利用败者树的调整方法和恰当的初始化可以简化败者树的建立过程：初始化败者树各内部结点和0号结点都为k（这就好像存在一个虚拟的编号为k的归并段，其中只有一个MinValue元素，它打败了0~k-1号的全部归并段，即这时已符合败者树的要求），然后从最后的k-1号归并段（2k-1号叶结点）向前逐个参加比赛，调整败者树，直到0号归并段（k号叶结点）为止；这种方法可以省去各内部结点对应的辅助单元；

在归并过程中，若某个归并段的元素都被取走，则将其对应的叶结点设置为最大值MaxValue，直到所有叶结点都为MaxValue，全部归并段就归并完成了；

B树：一棵m阶（m>2，即最少为3叉）的B树是一棵平衡的m路搜索树，可为空树；一棵非空m阶B树的性质：

根结点至少有2个子树；

其它内部结点至少有ceil(m/2)个子树，最多有m个子树；注，若m为unsigned int，则ceil(m/2)=(m+1)/2；

内部结点中的key比子树数少1个，key[0]不使用，或用来保存子树个数n（这样key数组实际有n+1个元素，而有的实现中则为n个元素），key[1]~key[n]保存实际的值，且正序排列；该结点的0号子树的key都＜key[1]，n号子树（最后一棵）的key都＞key[n]，而i号（0<i<n）子树的key在key[i]和key[i+1]之间；

各结点也可以是包含key和地址的索引项；

B树类似于稀疏的多级索引，所有的key分布在各内部结点，搜索过程是在一个结点内顺序或折半查找，如果找到了就直接返回，否则亦能判断范围，选中某棵子树继续向下一层查找；直到最底层为NULL指针，说明查找失败；

所有叶结点都在同一层，它们没有子树，指向子树的都是NULL，这些实际不存在的NULL子结点称为失败结点；

B树是从空树逐个插入key而建立的；B树插入key的过程与二叉搜索树类似，首先要从根开始搜索，如果找到则无需插入，否则搜索停止的位置即新key要插入的位置，由此可知，插入操作总是发生在叶结点上，需判断插入结点内key的个数是否满足B树的规定（(m+1)/2-1~m-1个key），如果超出了，则要将该结点拆分，方法是将结点中间的某个key（一般取key[(m+1)/2]）上移一层到父结点，必定是插入父结点的key[n+1]处，同时当前结点被分成两部分，父结点的key[n]对应左侧部分，新加的结点key[n+1]对应右侧部分；向父结点增加key可能导致连锁反应，最坏的情况是整棵B树增加一层；

从B树删除指定key后也要考虑不能使对应结点内key的个数＜(m+1)/2-1，否则需处理；

若该结点是叶结点，

且该结点的左、右兄弟结点中某个结点的key的个数＞(m+1)/2-1的，则从该兄弟结点借1个key到当前结点，为保证各结点的key之间的大小关系，借来的key不能直接替换删除留下的空位，应将当前结点的父结点对应的key放到删除留下的空位处，从兄弟结点借来的key放到父结点腾出的空位处；

且该结点所有的左、右兄弟结点的key的个数都是(m+1)/2-1，则在当前结点删除key后，可将剩余(m+1)/2-2个key与左兄弟或右兄弟合并，同时还要从父结点的key中取下1个来参与合并，若与左兄弟（i-1号子树）合并，则取父结点的key[i-1]；若与右兄弟（i+1号子树）合并，则取父结点的key[i+1]；从父结点删除1个key后也可能导致连锁反应，最坏的情况是整棵B树减少一层；

若该结点不是叶结点，需将其与相邻key逐层交换，直到叶结点，然后再用上述方法删除；相邻key是指要删除的key对应子树的最小key，或邻近的左子树的最大key，交换后不会破坏B树的性质，且能使该结点下移一层；

B+树是B树的变形，特点是：

Key（也可为含key和地址的索引项）都在叶结点层，从小到大顺序排列，且各叶结点组成一个有序链表；

内部结点只是保存对应子树中最大（或最小）的key本身，不会保存索引地址等内容，比B树的结点小很多；

内部结点内key的个数和子树的个数相同；

与B树一样，对结点子树的个数有限制，根结点至少2棵子树，其它内部结点至少有ceil(m/2)个子树，各内部结点最多有m个子树；

B+树除了一个指向根结点的指针外，还有一个指向key最小的叶结点的指针，亦即叶结点组成的链表的头指针；对B+树的搜索可以像B树那样从根结点开始，先在结点内查找，如果没有找到，可由结点内key的信息判断出在那棵子树，然后沿该子树继续搜索；但由于B+树内部结点只有key，所以不论是否在内部结点找到该key，都要继续搜索到叶结点，在叶结点中查找到地址等信息；

此外还可以直接从子结点链表开始顺序搜索，方便顺序遍历子结点；

B+树插入key和删除key与B树相似，也需要判断结点内key的数量是否满足规定，否则需分裂/借入或合并，不同之处是B+的操作都在叶结点上进行；

可扩充散列，二叉Trie树，目录表；Trie树，适合可变长key（如文件名）的多级索引；
