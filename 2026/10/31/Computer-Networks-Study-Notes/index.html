本文把计算机网络的核心概念整理成便于复习的提纲。内容依据文末参考文章重新归纳，并非原文转载。

408 计算机网络知识总览

复习时可按“分层职责 → 协议字段 → 工作过程 → 计算题型”逐层展开。一次访问网站会串起多个层次，拆开查看更容易区分寻址转发与端到端应用交互。

一、计算机网络与体系结构

计算机网络把多个自治计算机系统连接起来，使它们能够通信和共享资源。学习网络时，通常按层次划分功能：每层向上提供服务，并通过协议约定同层实体如何交换信息。

常见体系结构包括 OSI 七层模型和 TCP/IP 模型。复习时可先记住各层职责，再把协议、设备和数据单位对应起来：

层次 主要职责 常见协议或设备 常见数据单位
应用层 为应用程序提供网络服务 HTTP、DNS、FTP、SMTP 报文
传输层 进程间通信、复用与分用、可靠传输或拥塞控制 TCP、UDP TCP 段、UDP 用户数据报
网络层 逻辑寻址、路由选择与分组转发 IP、ICMP、路由器 IP 数据报
数据链路层 成帧、差错检测、介质访问控制 Ethernet、PPP、交换机 帧
物理层 在介质上传输比特 网线、光纤、中继器 比特

OSI 将应用层细分为应用、表示、会话三层；TCP/IP 常按应用层、传输层、网际层和网络接口层组织。两种模型的层次边界并非完全一一对应。

二、物理层

物理层关心如何把比特转换为适合介质传输的信号，以及接口、电气和机械特性。传输介质包括双绞线、同轴电缆、光纤和无线信道。

带宽描述信道可提供的最高数据传输能力；传播速率描述信号在介质中的传播速度。不要混淆发送时延与传播时延：

  • 发送时延 = 数据长度 ÷ 发送速率。
  • 传播时延 = 信道长度 ÷ 信号传播速率。
  • 总时延还可能包括处理时延和排队时延。

奈奎斯特定理讨论无噪声信道的码元速率上限，香农定理给出有噪声信道容量上限。它们分别受信号变化能力和信噪比约束。

三、数据链路层

数据链路层把网络层分组封装成帧，并处理相邻节点间的传输。常见考点包括：

  1. 成帧与透明传输：通过定界标志识别帧边界；字符填充或零比特填充避免数据内容被误认为边界标志。
  2. 差错检测与纠正：奇偶校验、循环冗余校验（CRC）等用于发现传输差错；是否能纠正差错取决于编码设计。
  3. 流量控制与可靠传输：停止等待、后退 N 帧（GBN）和选择重传（SR）使用确认与序号管理发送窗口。
  4. 介质访问控制：共享信道需要规则协调多个节点的发送，例如信道划分、随机访问或轮询。
  5. 局域网与交换：以太网、无线局域网和 VLAN 是常见主题；交换机依据链路层地址转发帧。

四、网络层

网络层负责跨网络传送分组。IP 提供尽力而为的数据报服务，路由器根据路由信息选择下一跳并转发分组。

  • IPv4：理解地址与子网掩码、CIDR、子网划分、ARP、DHCP 和 ICMP 的作用。
  • IPv6：地址空间更大，报文首部结构经过简化，并支持自动配置等机制。
  • 路由：区分路由选择（建立或计算路径）与分组转发（按转发表逐跳发送）。静态路由由管理员配置，动态路由由路由协议交换信息。
  • NAT：在私有网络与公网之间转换地址或端口；它不等同于路由本身。
  • 拥塞控制：网络负载超过资源承载能力时会产生排队和丢包，需要端系统或网络设备调节发送行为。

五、传输层

传输层把主机间通信扩展到进程间通信，使用端口号识别应用进程，并提供复用和分用。

UDP 面向数据报，首部开销小，不建立连接，也不保证可靠、有序交付。适合由应用自行控制时延或可靠性的场景。

TCP 面向连接，提供可靠、有序的字节流。复习时可按以下顺序梳理：

  • 三次握手建立连接，交换初始序号并确认双方收发能力。
  • 序号与确认号配合确认数据；超时重传、累计确认等机制支持可靠传输。
  • 接收窗口用于流量控制，避免发送方压垮接收端缓冲区。
  • 拥塞窗口用于拥塞控制，发送方根据网络反馈调整注入网络的数据量。
  • 四次挥手释放连接；主动关闭方通常经历 TIME_WAIT 状态。

流量控制针对接收端能力，拥塞控制针对网络承载能力，两者解决的问题不同。

六、应用层

  • DNS：把域名解析为 IP 地址，采用分层命名空间；缓存可减少重复查询。
  • HTTP：Web 的应用层协议；HTTP/1.1 常用持久连接，HTTPS 在 HTTP 与传输层之间加入 TLS 保护。
  • FTP：传统文件传输协议，控制连接与数据连接分离。
  • 电子邮件：SMTP 用于发送邮件，POP3 或 IMAP 用于收取和管理邮件；MIME 扩展邮件内容类型。
  • 客户机/服务器与 P2P：前者由服务器提供服务，后者允许节点兼具请求者与提供者角色。

七、复习建议

  1. 先按“层次—职责—协议—设备—数据单位”建立总表。
  2. 对可靠传输、滑动窗口、TCP 连接管理和子网划分，分别画状态图或做小例题。
  3. 对比容易混淆的概念：发送时延与传播时延、流量控制与拥塞控制、路由选择与分组转发、TCP 与 UDP。
  4. 刷题时标明题目涉及的层次，再从该层职责推导答案，避免只背协议名称。

八、重要机制展开

8.1 分层、封装与寻址

发送数据时，应用数据逐层向下交付。每层通常会添加本层控制信息：传输层形成 TCP 段或 UDP 数据报，网络层再加 IP 首部，链路层最后封装成帧。接收端按相反方向逐层解析。这个过程称为封装与解封装。

各层地址的作用范围不同：

  • 端口号标识一台主机上的应用进程。
  • IP 地址标识网络层通信中的源和目的主机，路由器据此转发。
  • MAC 地址用于一段链路上的帧交付；经过路由器转发后，下一段链路的帧地址会改变。

因此，端到端通信通常保持源、目的 IP 地址不变（不考虑 NAT 等地址转换），而每一跳的源、目的 MAC 地址都会根据当前链路重新封装。

8.2 物理层计算与交换方式

常见计算可以先统一单位，再代入公式：

  • 发送时延：L / R，其中 L 是比特长度，R 是发送速率。
  • 传播时延：d / v，其中 d 是传播距离，v 是介质中的传播速率。
  • 时延带宽积：传播时延 × 带宽，表示链路中可同时“在途”的比特数量。
  • 若分组长度为 L、链路带宽为 R，且经过多段存储转发链路，每段链路的发送时延通常都要计入；传播、处理和排队时延则按题目条件分别计算。

电路交换先建立专用通路，再传输并释放资源，适合持续通信但建立阶段有开销；报文交换以完整报文为转发单位，缓存需求较大；分组交换把报文切分为分组，便于共享链路，但可能出现排队、丢包和乱序，需要上层协议处理。

8.3 数据链路层的可靠传输

停止等待协议一次最多发送一个未确认帧。发送方发送后启动计时器，收到确认才发送下一帧；超时则重传。序号用于区分新帧和重复帧，避免确认丢失后重复交付。

滑动窗口允许多个帧处于传输途中：

  • GBN（后退 N 帧）通常采用累计确认；某个帧丢失后，发送方从该帧开始重传后续未确认帧，接收方一般只接收按序到达的帧。
  • SR（选择重传）允许接收方缓存窗口内乱序到达的帧，发送方只重传未被正确确认的帧，效率较高，但需要更多缓存并妥善设计序号空间。

窗口越大，越能覆盖传播往返期间的链路空闲时间；但窗口大小受到序号位数和协议规则限制。计算题要明确序号范围、发送窗口、接收窗口以及确认丢失或帧丢失的条件。

CRC 把比特串视为多项式并进行模二除法，发送方附加余数，接收方检查余数是否符合规则。它擅长检测常见突发错误，但 CRC 检错并不等于自动纠错或可靠重传；重传通常由链路协议或更高层完成。

8.4 以太网、交换机与 VLAN

以太网帧携带源、目的 MAC 地址和上层协议类型等信息。交换机学习收到帧的源 MAC 地址及其端口，形成转发表；转发时查目的 MAC，已知则定向发送，未知或广播帧则按规则泛洪到其他端口。

交换机主要工作在数据链路层。VLAN 将一个物理局域网划分为多个逻辑广播域；不同 VLAN 之间通信通常需要网络层设备或三层交换功能。连接同一 VLAN 的接入口一般承载单个 VLAN，交换机之间的干道链路可以用标签区分多个 VLAN 的流量。

8.5 IPv4 子网与路由

CIDR 用“地址/前缀长度”表示网络部分。例如 /24 表示前 24 位是网络前缀，剩余位用于主机部分。判断两个 IPv4 地址是否在同一子网，可将地址与子网掩码逐位相与，再比较网络地址。

传统子网题可按以下步骤处理：

  1. 把前缀长度换算成掩码，确认网络位和主机位。
  2. 计算网络地址：IP 地址按位与子网掩码。
  3. 计算广播地址：网络位不变、主机位全为 1。
  4. 根据题目要求确定可用主机地址范围；点到点链路、特殊前缀等情况按题设规则处理。

路由器收到分组后，通常检查目的 IP 地址并执行最长前缀匹配：若多条路由都匹配，选择前缀更长、匹配更具体的一条，再将分组发往相应下一跳。路由表中的默认路由用于没有更具体匹配项时的转发。

ARP 在 IPv4 局域网中根据目标 IPv4 地址查询对应的链路层地址。若目标主机不在本地子网，主机通常解析默认网关的 MAC 地址，把帧发给网关；IP 分组的最终目的地址仍是远端主机。

8.6 TCP 连接建立、释放与可靠传输

三次握手可以用序号关系理解：客户端发送 SYN 并给出初始序号；服务器用 SYN+ACK 确认客户端序号，同时给出自己的初始序号；客户端再用 ACK 确认服务器序号。双方因此确认彼此的发送和接收能力，并同步连接状态。

TCP 的确认号通常表示接收方下一步期望收到的字节序号。累计确认能够一次确认此前连续收到的数据；若中间出现缺口，后续到达的数据可能需要缓存，发送方则依靠超时或快速重传恢复丢失部分。

连接释放需要双方分别关闭各自方向的数据发送，因此常见过程包含 FIN、ACK、FIN、ACK。主动关闭方进入 TIME_WAIT，以便在必要时重发最后的确认，并让旧连接中的延迟报文自然消失。

8.7 流量控制与拥塞控制的区别

流量控制保护接收端：接收方通过通告窗口说明还能接收多少数据，发送方不能超过该接收能力。拥塞控制保护网络：发送方根据丢包、确认和时延等反馈调节拥塞窗口，避免持续向网络注入过量数据。

经典 TCP 拥塞控制会涉及慢开始、拥塞避免、快重传和快恢复。学习时重点掌握：

  • 拥塞窗口与接收窗口共同限制可发送但尚未确认的数据量。
  • 慢开始阶段窗口增长较快，达到阈值后通常进入拥塞避免。
  • 检测到拥塞后，发送方会降低发送速率并调整阈值。
  • 快重传利用重复 ACK 较早发现丢失；快速恢复避免每次丢包都完全回到初始发送速率。

具体窗口变化题必须依据题目指定的 TCP 版本、初始窗口、阈值和丢包信号推演，不能把某一种教材模型当成所有实现的固定行为。

九、常见易错点

易混概念 区分方法
带宽与传播速率 带宽描述单位时间可发送多少数据；传播速率描述信号在介质中前进多快
发送时延与传播时延 前者由数据量和发送速率决定；后者由距离和信号速度决定
MAC 地址与 IP 地址 MAC 用于当前链路交付；IP 用于跨网络寻址与转发
ARP 与 DNS ARP 在局域网内解析 IPv4 到链路层地址；DNS 将域名解析为 IP 地址
流量控制与拥塞控制 前者匹配接收端能力；后者适应网络承载能力
TCP 与 UDP TCP 提供连接、可靠有序字节流；UDP 提供低开销数据报，不承诺可靠交付
路由选择与转发 路由选择决定路径或下一跳；转发按转发表处理具体分组

十、做题检查清单

读题后先标出协议层次和通信范围，再确认题目问的是时延、容量、可靠性、寻址还是转发。计算题写清单位、网络前缀、序号空间与窗口假设；过程题按发送端、网络和接收端分别列步骤；比较题先给出共同点，再围绕服务对象、状态、首部和保证逐项对照。

十一、重点题型与推导

11.1 端到端时延与流水传输

若一个长度为 L bit 的分组经过 n 条速率相同为 R 的存储转发链路，忽略处理和排队，每条链路的发送时延都要计入，总发送时延为 nL/R；传播时延则按每条链路的长度和介质速率求和。若发送的是多个等长分组，后续分组可能与前一分组流水传输，不能简单把单个分组的全部时延乘以分组数。先画出各链路上的发送时间线，再计算最后一个比特到达目的端的时刻。

带宽时延积可估算“填满管道”所需的数据量。若往返时延为 RTT、链路速率为 R，想持续占满链路，发送方需要允许约 R × RTT bit 的数据处于未确认状态；若接收窗口或拥塞窗口更小，吞吐量会受窗口限制。

11.2 停止等待与滑动窗口效率

设帧发送时间为 T_f，往返传播与确认时间合计为 RTT，且确认帧发送时间可忽略。停止等待协议在无差错时的利用率近似为：

U = T_f / (T_f + RTT)

当传播时间远大于发送时间时，发送方大部分时间在等待确认；滑动窗口的作用是允许多个帧同时在途。忽略确认开销、差错和窗口限制时，要达到接近满速，窗口至少要覆盖一个往返期间可发送的帧数。题目若给出帧长、链路速率、传播时延和窗口大小，可先算每帧发送时间，再比较窗口能否填满链路。

对有 m 位序号的协议，序号空间大小为 2^m。选择重传为了避免把旧帧误判为新帧，常见约束是发送窗口和接收窗口大小不超过序号空间的一半；后退 N 帧协议的接收窗口通常为 1，发送窗口最大值则受序号空间约束。答题时应以课程指定协议和题目条件为准。

11.3 子网划分例题方法

例如给定 192.168.10.77/26：前缀长度 26 表示主机位有 6 位，子网块大小为 2^6 = 64 个地址。最后一个八位组的网络块边界是 0、64、128、192；77 落在 64 至 127 之间，因此网络地址是 192.168.10.64，广播地址是 192.168.10.127。在传统普通子网题的约定下，可用主机范围为 .65 至 .126。若题目涉及 /31 点到点链路或 /32 主机路由，则不能机械套用“网络地址和广播地址不可分配”的普通规则。

判断目的地址是否本地可达时，对本机地址和目的地址分别与掩码相与；结果相同则同网段，否则发给默认网关。转发路由时执行最长前缀匹配，而不是简单挑选数值最小的路由项。

11.4 DNS 查询过程

DNS 使用分层的域名空间和资源记录。A 记录映射到 IPv4 地址，AAAA 记录映射到 IPv6 地址，CNAME 表示别名，NS 记录指出负责某个区域的名称服务器，MX 记录用于邮件交换。

一次典型解析通常先检查浏览器、操作系统和本地解析器缓存；若无结果，递归解析器代表客户端继续查询。递归器可从根服务器获得顶级域名服务器线索，再获得目标域的权威服务器地址，最后向权威服务器查询记录并缓存结果。缓存的有效时间受 TTL 控制。递归查询表示服务器负责替请求者继续完成解析；迭代查询则由响应方返回下一步可查询的服务器信息。

DNS 既可通过 UDP 传输，也会在需要时使用 TCP，例如区域传送或响应超过可用 UDP 载荷等情形。排查解析问题时，区分“本地缓存旧记录”“递归解析器不可达”“权威记录错误”和“记录 TTL 尚未过期”等原因。

11.5 DHCP 地址配置

DHCP 常见的初始分配过程可记作 DORA：客户端广播 Discover 寻找服务器；服务器回复 Offer 提议租约；客户端发送 Request 选择提议；服务器用 ACK 确认。报文中还会携带子网掩码、默认网关、DNS 服务器和租期等配置。

客户端续租时通常优先向原 DHCP 服务器请求延长租约；若无法联系原服务器，则可在后续阶段广播请求。DHCP 使用 UDP，并通过客户端和服务器端口区分通信方向。跨子网部署时，常需 DHCP 中继转发客户端广播请求。

11.6 TCP 序号、窗口与吞吐

TCP 的序号按字节编号，而不是按报文段编号。若某段数据从序号 1000 开始、载荷长度为 500 字节，接收方连续收到该段后，累计确认号通常是 1500，表示下一个期待的字节序号是 1500。SYN 和 FIN 也各自占用一个序号空间位置。

发送方受两个窗口共同约束：接收窗口 rwnd 反映接收端缓冲能力，拥塞窗口 cwnd 反映发送方允许注入网络的数据量。可发送的未确认数据量大致不超过 min(rwnd, cwnd)。实际吞吐还受往返时延、丢包、MSS、接收应用读取速度和实现算法影响。

RTT 估计值不是简单采用最近一次测量。TCP 根据多次采样平滑估计往返时间，并根据变化幅度设置重传超时，避免网络波动时过早重传。教材题会简化该过程，务必跟随题目给定规则。

11.7 网络应用交互示例

浏览器访问一个 HTTPS 网站，可按以下层次理解：

  1. DNS 解析域名，获得服务端地址。
  2. 客户端与服务器建立传输层连接；具体连接机制取决于所用传输协议与 HTTP 版本。
  3. 使用 TLS 等机制协商加密参数并验证服务器身份。
  4. 客户端发送 HTTP 请求，携带方法、目标资源和首部；服务器返回状态码、首部与响应内容。
  5. 浏览器解析 HTML，再请求页面引用的 CSS、脚本、字体和图片等资源。

这说明“网页打不开”并不一定是 HTTP 本身的问题：DNS、路由、传输连接、TLS 证书、服务器状态和资源 URL 都可能导致不同故障。分层排查时应从名称解析开始，再验证 IP 连通、传输端口、TLS 握手和 HTTP 状态码。

十三、补充专题

13.1 信道容量、编码与调制

数字数据需要映射为适合信道传播的信号。基带传输直接使用数字信号；带通传输则先将信号调制到适合介质的频带。调制可改变载波的幅度、频率或相位。码元是信号的基本波形单位，一个码元可以携带一个或多个比特，因此码元速率与比特率不能直接等同。

理想无噪声信道的奈奎斯特上限常写作 C = 2B log₂V，其中 B 为带宽、V 为可区分信号状态数；有噪声信道的香农容量为 C = B log₂(1 + S/N)，其中 S/N 是线性信噪比。计算时要注意若题目给的是分贝值，先用 S/N = 10^(SNRdB/10) 转为线性比值。两者描述不同约束，实际速率不能超过信道条件允许的容量。

常见多路复用方法：

  • 频分复用 FDM：不同用户占用不同频带，可同时发送。
  • 时分复用 TDM：用户轮流占用时隙；统计时分复用按需分配时隙，效率通常高于固定时隙。
  • 波分复用 WDM：在光纤中用不同波长的光载波承载多路信号。
  • 码分复用 CDM/CDMA：用户共享时间和频率资源，以近似正交的码序列区分信号。相关计算常用码片向量点积判断正交性，并用接收向量与目标码序列相关运算恢复发送数据。

13.2 差错检测、海明码与 CRC

码距是两个等长码字对应位不同的位数。若一个编码方案的最小码距为 d_min，理论上最多可检测 d_min - 1 位错误，最多可纠正 floor((d_min - 1)/2) 位错误。检测与纠错能力有不同要求；不要把“能检测”误写为“能自动恢复原数据”。

海明码通过多个校验位覆盖不同位置的比特。若数据位为 m、校验位为 r，常见单错纠正码要求 2^r ≥ m + r + 1，让校验结果（综合 syndrome）能指出错误位置并包含“无错”状态。扩展海明码再增加整体奇偶校验位，可实现单错纠正、双错检测（SECDED）。

CRC 将比特串解释为二进制多项式。若生成多项式的最高次为 r，发送端在数据后补 r 个 0，用模 2 除法求余数，再用余数替换补上的 0；接收端对整个码字除以同一生成多项式，按余数判断是否发现差错。模 2 运算不借位、不进位，相当于逐位异或。CRC 的检错强度与生成多项式和错误模式有关，不能据此推断所有错误都必能发现。

13.3 共享介质访问与无线局域网

CSMA 的基本思想是发送前先监听信道。CSMA/CD 用于传统共享式半双工以太网：先监听再发送，发送中继续检测冲突；检测到冲突后发送拥塞信号并随机退避，再尝试重传。二进制指数退避在第 k 次冲突后，从有限整数范围内选取随机时隙数；常见以太网模型将上限指数封顶在 10。以 10 Mb/s、512 bit-time 为一个时隙时，时隙长度为 51.2 μs。具体题目要区分“第几次冲突后计算退避”和“当前是第几次重传”。

无线局域网通常采用 CSMA/CA，而不是 CSMA/CD。无线节点难以边发送边可靠检测碰撞，因而通过随机退避、确认帧和虚拟载波侦听降低碰撞影响。RTS/CTS 可帮助缓解隐藏站问题：互相听不到的发送端可能同时向同一接收端发送；接收端通过 CTS 告知周边节点预约信道。它不能消除所有冲突，也会增加控制帧开销。

13.4 交换机、生成树与局域网转发

交换机学习源 MAC 与入端口的对应关系，并依据目的 MAC 查表转发。若目标地址尚未学习，通常在同一 VLAN 的其他端口泛洪；广播帧也限制在相应广播域内。MAC 表项可因老化而失效，交换机随后重新学习。

若二层网络存在环路，广播帧和未知单播可能无限循环，造成广播风暴和 MAC 表震荡。生成树协议通过逻辑阻塞部分冗余链路，形成无环的活动拓扑；链路故障时可重新计算并启用备用路径。VLAN 把广播域逻辑隔离，但同 VLAN 内通信仍是二层转发，不同 VLAN 通信需要三层转发。

13.5 IPv4 分片、ICMP 与 NAT

当 IPv4 数据报长度超过下一段链路的 MTU，且允许分片时，路由器可把数据报拆成多个片段。片段共享标识字段，通过片偏移和更多分片标志描述位置与是否还有后续片段；片偏移以 8 字节为单位，所以除最后一片外的数据长度通常需要满足 8 字节对齐。重组通常由最终目的主机完成，任一片丢失都会影响整个原始数据报的重组。

IPv6 路由器不在转发途中对数据包分片；源主机根据路径 MTU 调整数据包大小，必要时由源端使用分片扩展首部。遇到“分片在哪一端完成”这类问题，要区分 IPv4 与 IPv6。

ICMP 用于报告 IP 层错误和网络诊断，例如目的不可达、超时和回显请求/应答。ping 通常利用 ICMP 回显报文探测可达性与往返时间；traceroute 类工具利用 TTL/Hop Limit 逐步到期触发 ICMP 超时报文，以推测路径中的路由器。设备或防火墙可能过滤相关报文，因此没有响应不能单独证明目标主机不可达。

NAT 在地址边界上改写 IP 地址，NAPT 还会改写传输层端口，从而让多个内部流共享外部地址。改写源 IP 或端口后，相关校验和也要相应更新；UDP 校验和计算会涉及 IP 伪首部，因此地址转换可能影响传输层校验。NAT 的状态表把返回流量映射回内部主机；它缓解地址短缺，但会改变端到端寻址透明性。

13.6 路由算法对比

算法/协议 信息视角 典型算法 复习要点
距离向量 邻居周期性通告到各目的网络的距离 Bellman-Ford 思想 信息逐跳传播；可能出现慢收敛和计数到无穷，RIP 使用跳数度量并限制最大可达跳数
链路状态 向区域内路由器扩散链路状态，形成拓扑数据库 Dijkstra 最短路径 每台路由器据相同拓扑独立计算最短路径；OSPF 属于链路状态路由协议
路径向量 通告可达前缀及经过的自治系统路径 按策略选路 BGP 在自治系统之间交换路由，选择不只由最短距离决定，还受策略影响

距离向量题常用 D_x(y) = min_v { c(x,v) + D_v(y) } 更新本地到目的 y 的估计；链路状态题则从源点出发逐次确定当前代价最小的未确定结点，并松弛其邻边。题目给邻接矩阵时，先标清链路代价与不可达值，避免把“未知”当成零代价。

13.7 邮件、文件传输和 Web 协议

  • SMTP 用于客户端向邮件服务器提交邮件，以及邮件服务器之间转发邮件。
  • POP3 通常以下载邮件为主，客户端本地保存邮件；IMAP 支持服务器端邮箱管理和多设备同步。具体同步行为取决于客户端配置。
  • FTP 把控制连接与数据连接分开；主动/被动模式的差别体现在数据连接由哪一端发起，常影响防火墙和 NAT 环境下的连接建立。
  • HTTP 是无状态的请求/响应协议。请求由方法、目标资源、首部和可选内容组成；响应包含状态码、首部和可选表示。常见状态码类别为 2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误。
  • HTTPS 是在 HTTP 通信中使用 TLS 保护连接。TLS 负责协商加密参数、认证服务器（通常通过证书）并建立会话密钥；加密保护不能替代应用自身的授权和输入校验。

十四、各章自测问题

  1. 为什么无噪声信道的最高数据率受带宽和信号状态数共同影响？有噪声时还要考虑什么量？
  2. 一个 m 位序号协议的发送窗口为什么不能只看序号个数，还要看接收窗口和旧帧的区分条件？
  3. 在 10 Mb/s 以太网中，512 bit-time 对应多长时间？冲突后随机退避的最大等待范围如何求？
  4. 主机访问异网段目标时，第一跳帧的目的 MAC 是最终服务器还是默认网关？IP 目的地址又是什么？
  5. IPv4 片偏移以什么为单位？为什么通常只有最后一片可不满足 8 字节对齐？
  6. TCP 的序号按字节还是按段计数？接收窗口与拥塞窗口分别保护谁？
  7. DNS 递归解析器、根服务器、TLD 服务器和权威服务器在一次解析中各提供什么信息？
  8. CSMA/CD 与 CSMA/CA 分别用于什么共享介质环境？RTS/CTS 缓解哪类问题？

建议先口头回答，再分别做一题计算题或报文流程题；答错时回到“字段—状态变化—结果”重新推导，而不是只记选项。
